# ADR-005 — Identifier Strategy

**Status:** Accepted  
**Gate:** G2

## Decision

MK1 uses opaque UUIDv4 identifiers generated by the application for new domain entities.

## Rules

- IDs are stable for the lifetime of the entity.
- IDs never encode parent IDs, labels, coordinates or database collection names.
- Moving or renaming an entity never changes its ID.
- External/legacy IDs are stored separately as migration metadata when required.
- Presentation code must treat IDs as opaque strings.

## Rationale

UUIDv4 is supported directly by the Node.js runtime, avoids database-specific identity coupling and supports deterministic domain boundaries without introducing a new ID dependency.

## Consequences

G3 persistence schemas must use a consistent `id` field as domain identity and may use MongoDB `_id` only as an infrastructure concern if needed.
